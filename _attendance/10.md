# 第10回の出席確認クイズ。
#   theme    : クイズのテーマ（一覧ページに表示される）
#   q        : 問題文
#   choices  : 選択肢（表示順はページを開くたびに入れ替わる）
#   answer   : 正解の選択肢の番号（0 が最初の選択肢）
#   explain  : 不正解のときに表示される解説
number: 10
theme: AIによる批判的検証と評価
questions:
- q: 自分の提案の弱点をAIに指摘させるプロンプトとして、最も効果的なものはどれでしょうか。
  choices:
  - 「あなたは厳しい審査員です。この提案の弱点を、重要な順に5つ挙げてください」
  - 「この提案に賛成ですか」
  - 「この提案はどうですか」
  - 「この提案を褒めてください」
  answer: 0
  explain: 批判者の役割と出力形式（数、順序）を指定すると、具体的で使える指摘が得られます。漠然と感想を聞くと、当たり障りのない肯定的な回答になりがちです。
- q: AIの安全性の分野でいう「レッドチーミング」とは何でしょうか。
  choices:
  - AIの画面を赤色にすること
  - わざと問題のある出力を引き出そうと試して、弱点や危険性を洗い出すこと
  - AIを赤字の企業に導入すること
  - AIのチームに赤い制服を着せること
  answer: 1
  explain: レッドチーミングは、攻撃者や悪意ある利用者の立場でAIを試し、有害な出力や抜け穴を見つける検証手法です。自分の提案に対して同じ発想で弱点を探すこともできます。
- q: 「ファインチューニング」の説明として適切なものはどれでしょうか。
  choices:
  - AIの利用料金を細かく設定すること
  - 学習済みのモデルに追加のデータを学習させて、特定の用途に合わせて調整すること
  - AIの画面の文字を細かく整えること
  - AIの回答を人が手作業で修正すること
  answer: 1
  explain: ファインチューニングは、汎用モデルを特定分野のデータで追加学習させる手法です。プロンプトの工夫だけでは足りない場合に、企業が自社向けのAIを作る方法のひとつです。
- q: AIの出力の質を、別のAIに採点させる方法は何と呼ばれるでしょうか。
  choices:
  - コンテキストウィンドウ
  - ディープフェイク
  - トークン
  - LLM-as-a-judge（審判としてのLLM）
  answer: 3
  explain: LLM-as-a-judge は、AIの出力を別のAI（または同じAI）に評価させる方法です。大量の出力を効率よく比較できますが、評価するAIにも偏りがあるため、人の確認と組み合わせます。
- q: AI活用記録に「採用しなかった出力とその理由」も書く意義として、最も適切なものはどれでしょうか。
  choices:
  - AIの失敗を報告してAI開発企業に知らせるため
  - 採用しなかった出力は後で使い回せるため
  - 記録が長いほど評価が高くなるため
  - 何を自分で判断したかが伝わり、AIの寄与と自分の思考を区別して示せるため
  answer: 3
  explain: 採用・修正・不採用の判断とその理由を書くことで、出力をどう吟味したかが見えます。これが「AI活用の透明性」の評価につながります。
